Two simple ways to play

These steps are for CYDs and a Pi Hub running v1.7 or newer. No firmware change is needed to switch between the two setups.

A · One table

CYD + tablet

CYD → Tablet browser

  1. Power on. Connect the USB-C battery. Set the CYD's table number, from 1 to 30.
  2. Join Wi-Fi. On the CYD, tap WIFI and join your network. Connect the tablet to the same network.
  3. Open your table. For Table 1, open http://scorekeeper-t1.local in the tablet browser. Change t1 to your table number.
  4. Play. Start a manual match on the CYD. Tap scores on the CYD; watch them update on the tablet.

The CYD hosts its own scoreboard. No Pi or internet connection is needed for this local view.

B · Multiple tables

Pi server + CYDs

CYDs → Pi → Browser

  1. Power on. Start the Pi with Scorekeeper Hub installed. Connect each CYD to its USB-C battery.
  2. Use one network. Connect the Pi, CYDs and viewing tablet or computer to the same router.
  3. Number the tables. Give each CYD a different table number, from 1 to 30. Each CYD finds the Pi automatically.
  4. Open and play. Browse to http://PI-IP:8081, replacing PI-IP with your Pi's address. Start matches on the CYDs. Tap Jumbotron for one table.

On the Pi itself, open http://localhost:8081.

Both at once: each CYD's direct table URL keeps working while that same CYD reports to the Pi. A tablet can show one table while the Pi shows all tables.

Scores are entered on the CYD. Closing a viewing browser does not stop scoring.

Find your table's scoreboard

Use http://scorekeeper-tNUMBER.local, replacing NUMBER with the number set on the CYD.

Table 1http://scorekeeper-t1.local Table 2http://scorekeeper-t2.local Table 30http://scorekeeper-t30.local

Tables 1 through 30 follow the same pattern. Type the full address, including http://, into the browser's address bar.

These are local addresses. Your tablet or computer must be on the same network as the CYD. If a .local name does not resolve, use the CYD's local IP address instead.

Installing from scratch?

If your CYD already has v1.7 or newer installed, use Quick setup. Arduino IDE is only needed when installing or updating firmware.

For one CYD + tablet

  • A CYD with enclosure and Scorekeeper v1.7 or newer
  • A USB-C battery and suitable cable
  • A tablet or computer with a browser
  • A shared Wi-Fi network

For a Pi server + multiple CYDs, also bring

  • A Raspberry Pi with Raspberry Pi OS, microSD card and power supply
  • A keyboard and screen, or SSH access to the Pi
  • The Pi Scorekeeper Hub v1.7 or newer package from the repository's scorekeeper folder
  • A unique table number on each CYD

Open the project repository and look in the scorekeeper folder for the current package and its README.

One network: use a router that lets connected devices communicate with each other. Guest Wi-Fi with device isolation can block both setups.

Install the Pi Scorekeeper Hub

Only the multi-table Pi setup needs this section. Use the current v1.7 or newer package and its included README.

1

Update Raspberry Pi OS

Open a terminal on the Pi and run:

sudo apt update
sudo apt full-upgrade -y
sudo reboot

After the reboot, reconnect to the Pi and open the terminal again.

2

Copy the current ZIP to the Pi

Download the ZIP from the repository's scorekeeper folder, then place it in the Pi user's Downloads folder. You can use a browser, USB drive, file sharing, or scp.

3

Extract the app

First list the files so you can confirm the ZIP's exact name:

cd ~/Downloads
ls

Then extract it. Replace YOUR_DOWNLOADED_ZIP.zip below with the exact filename you downloaded.

mkdir -p ~/scorekeeper-hub
unzip "YOUR_DOWNLOADED_ZIP.zip" -d ~/scorekeeper-hub
cd ~/scorekeeper-hub
ls
If unzip is missing: install it with sudo apt install unzip -y, then repeat the extraction command.
4

Follow the package installer

Open the README included in the extracted package and use its install command. Package contents can change, so its instructions are the authority for required software and paths.

find ~/scorekeeper-hub -maxdepth 2 -iname "README*" -print

If the package contains an install.sh file and its README tells you to use it, change into that file's folder and run:

chmod +x install.sh
./install.sh

Run the installer as your normal Pi user. It will request administrator access where needed. If it reports an error, keep the complete message for troubleshooting.

Check the Pi background service

The Pi app normally runs as a system service named scorekeeper-hub. Check it with:

sudo systemctl status scorekeeper-hub

Look for active (running). Press q to leave the status screen.

Start it now and at every boot

sudo systemctl enable --now scorekeeper-hub

Restart after a change

sudo systemctl restart scorekeeper-hub
sudo systemctl status scorekeeper-hub

Read recent logs

sudo journalctl -u scorekeeper-hub -n 100 --no-pager
“Unit not found”? The app's installer has not created the service yet, or the package uses a different service name. Return to the package README instead of creating a guessed service file.

Find and open the Pi Hub

If your Pi's hostname is scorekeeper and mDNS is available, try this address from another device on the same network:

http://scorekeeper.local:8081

If that does not open, find the Pi's IP address:

hostname -I

Choose the Pi's address on the same network as your CYDs, for example:

http://192.168.1.42:8081

You can also check the Pi's hostname:

hostname
Tip: bookmark the working address. A router may assign a different IP later. A hostname such as scorekeeper.local helps when it matches your Pi's configured hostname and mDNS works on both devices.

Update or reinstall the Pi Hub

Keep the previous working folder until the new version has been tested. This gives you a simple rollback.

  1. Download the replacement ZIP from the repository.
  2. Stop the running service.
  3. Back up the current app folder, configuration and score database. The shared database may live outside the app folder; check the package README.
  4. Extract the replacement package into a clean folder.
  5. Follow the new package README or installer, then restart and test.
sudo systemctl stop scorekeeper-hub
cp -a ~/scorekeeper-hub ~/scorekeeper-hub-backup

# Extract the new ZIP by following the install steps above.
# Then follow its README before starting the service again.

sudo systemctl start scorekeeper-hub
sudo systemctl status scorekeeper-hub
Reinstalling? Do not delete the old folder or overwrite configuration until you know where the package stores settings and data. Back those items up first.

Install or update CYD firmware

Use the v1.7 or newer CYD sketch supplied with your release. It supports the local table webpage and Pi reporting together. Skip this section if your device is already ready to play.

The exact board and serial-port names depend on the referee hardware and your computer. Use the markings on the board and the project's firmware notes—do not choose a board at random.

1

Install Arduino IDE

Download and install the current Arduino IDE from the official Arduino website for your operating system.

2

Open the firmware sketch

In the repository's scorekeeper firmware folder, locate the .ino file. Open it in Arduino IDE. If the sketch uses a folder of the same name, keep all companion files together.

3

Connect and identify the board

Disconnect external power from the referee device, then connect it to the computer with a USB data cable. Read the board model printed on the hardware or check the project documentation.

4

Select the board and port

In Arduino IDE, choose Tools → Board and select the model that matches the device. If its board package is not installed, Arduino IDE will offer it through Boards Manager.

Next choose Tools → Port. A reliable way to identify it is to note the port list, unplug the device, then reconnect it—the newly appearing port is usually the correct one.

5

Verify and upload

Select Verify first. If Arduino IDE reports a missing library, install only the library named by the compiler and confirmed by the project documentation. When verification succeeds, select Upload and wait for completion before unplugging the device.

Some boards require a reset/boot button sequence. Use the instructions for the exact board model if Arduino IDE cannot begin the upload.

Important: flashing replaces the firmware already on the referee device. Save a known-good firmware copy before changing it.

Troubleshooting

The direct CYD page does not open

  • Check power and confirm the CYD and tablet joined the same Wi-Fi.
  • Check the CYD table number. Table 3 uses http://scorekeeper-t3.local.
  • Use http:// and enter the address directly, rather than searching for it.
  • If .local fails, try the CYD's local IP address. Do not add the Pi port :8081 to a direct CYD address.
  • Avoid guest networks or router settings that isolate devices.

One table is missing from the Pi

Check that every CYD has a unique table number and shares the Pi's network. Confirm the Pi Hub is running. The direct table webpage can still be used while you check the hub connection.

The Pi Hub page does not open

  • Confirm the Pi and viewing device are on the same network.
  • Try both http://scorekeeper.local:8081 and the Pi's IP address with :8081.
  • Check sudo systemctl status scorekeeper-hub.
  • Read the service logs for the actual error.
  • Confirm something is listening on port 8081:
sudo ss -ltnp | grep ':8081'

scorekeeper.local does not work

Use the numeric IP address. If that works, the app is running and the remaining issue is local hostname/mDNS discovery. On Raspberry Pi OS, check the mDNS service:

sudo systemctl status avahi-daemon

The service starts and then stops

Look at the latest logs. Common clues include a missing file, a wrong path, a port already in use, or a permission problem:

sudo journalctl -u scorekeeper-hub -n 100 --no-pager

Arduino IDE shows no serial port

  • Try a known USB data cable; many charging cables carry no data.
  • Try another USB port and reconnect the device.
  • Close other programs that may be using the serial port.
  • Install the USB driver only if the exact board documentation requires one.

Firmware upload fails

  • Recheck the selected board model and serial port.
  • Disconnect anything that could interfere with flashing, following the board maker's instructions.
  • Use the exact board's documented boot/reset procedure.
  • Copy the full error message; its first specific error is usually the most useful clue.

Backups and shutdown

  • Shut down the Pi cleanly before removing power: sudo poweroff.
  • Disconnect the referee device's external power before connecting USB unless its hardware documentation explicitly says otherwise.
  • Back up configuration, stored data, the known-good firmware, and the working app folder before updating.
  • Do not change wiring or pin assignments without the correct hardware diagram.
Ready to play: start a test match, add a point on the CYD, and confirm it appears in the browser. For a Pi setup, check the same table on the Hub too.
